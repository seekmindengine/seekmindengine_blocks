# Block 名称

[文档首页](../README.md) / [Block 目录](../README.md#block-目录) / Block 名称

## 概览

用一到两句话说明该 Block 的实际行为、输入输出关系和最重要的使用边界。模块页围绕功能、配置和使用方法展开，以当前产品版本的模块定义和 API 为依据，不得根据名称补写能力。

## 模块信息

| 项目 | 内容 |
|---|---|
| 分类 | 所属分类 |
| Block ID | `block_id` |
| 处理模型 | 连续样本流 / 消息 / 混合 |
| 典型位置 | Source / Transform / Sink / Control |

## 何时使用

- 描述适合使用的工程任务。
- 描述选择该 Block 而不是相近 Block 的理由。
- 必要时明确不适用的场景。

## 输入与输出

| 方向 | 端口 | 数据类型 | 说明 |
|---|---|---|---|
| 输入 | `in` | `float` | 输入约束 |
| 输出 | `out` | `float` | 输出语义 |

连接前必须明确数据类型、采样率、向量长度、消息格式和端口数量。不要把参数表当成接口契约的替代品。

## 参数

| 参数名称 | 类型 | 说明 | 默认值 | 运行时可调 |
|---|---|---|---|---|
| **Parameter** | 类型 | 参数的实际作用和单位 | 默认值 | ✓ / ✗ |

参数名称、类型、默认值、枚举选项和运行时可调性必须从产品集成版本的模块定义、callback 和 Block API 取证。可以折叠重复的 GUI Line 1..N 参数，但不得增加实际定义中不存在的参数。

## 工作原理

用简短步骤、公式或数据流描述处理逻辑。重点解释可观察行为，不复述底层实现源码。

## 快速示例

```text
[Source] -> [Block] -> [Sink]
```

给出一组可运行的关键参数，并说明用户应观察到什么结果。示例应能用于验证配置，而不只是展示连接关系。

## 性能与部署

- 说明采样率、缓冲、时延、CPU、内存或 I/O 开销。
- 说明硬件、网络或文件系统相关限制。
- 给出生产或长时间运行时的建议。

## 故障排查

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| 无输出 | 类型或端口不匹配 | 对照“输入与输出”检查连接 |

## 修订检查

- [ ] Block ID、label、参数、默认值和端口与产品集成定义一致
- [ ] 处理关系由实现或 API 确认，没有按算法名称猜测
- [ ] PMT、PDU、标签和 callback 的描述与实现一致
- [ ] 示例未把可选的 Throttle、采样率或标签行为写成通用强制规则
- [ ] 性能数字附测试环境和方法；否则只说明影响因素
- [ ] 页面聚焦当前模块的功能与使用，参数和行为已按实际实现核对
