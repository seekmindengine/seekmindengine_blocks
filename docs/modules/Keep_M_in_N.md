# Keep M in N 模块

[文档首页](../../README.md) / [Block 目录](../../README.md#block-目录) / Keep M in N

## 概览

Keep M in N 模块按照周期 `N` 从输入流中保留 `M` 个项目，并丢弃同一周期中的其余项目。它可用于周期性数据筛选、时隙提取、帧内字段选择和调试降载。

该模块不执行滤波。若用于连续信号降采样，仍需自行处理抗混叠问题。

## 模块信息

| 项目 | 内容 |
|---|---|
| 分类 | Stream Operators（流操作） |
| Block ID | `blocks_keep_m_in_n` |
| 处理模型 | 连续样本流 |
| 典型位置 | Transform（处理与变换） |
| 执行支持 | Python / C++ |

## 何时使用

1. **周期抽取**  
   每 N 个样本只保留其中 M 个

2. **时隙选择**  
   从周期性帧结构中取出指定时隙

3. **数据降载**  
   减少后续模块处理的数据量

4. **门控采样**  
   周期性开启和关闭数据通路

5. **帧内字段提取**  
   提取每帧固定位置的数据段

## 输入与输出

| 方向 | 端口 | 模型 | 数据类型 | 说明 |
|---|---|---|---|---|
| 输入 | `默认` | 样本流 | 由数据类型参数决定 | 连续样本流端口 |
| 输出 | `默认` | 样本流 | 由数据类型参数决定 | 连续样本流端口 |

> 数据类型、向量长度和标签传播规则属于连接契约。即使流程可以启动，配置不一致仍可能造成错位或语义错误。

## 参数

| 参数名称 | 类型 | 说明 | 默认值 |
|---------|------|------|--------|
| **Type** | 枚举 | 数据类型：complex、float、int、short、byte | float |
| **M** | 整数 | 每个周期保留的样本数 | 1 |
| **N** | 整数 | 周期长度 | 2 |
| **initial offset** | 整数 | 初始偏移量 | 0 |

## 参数说明

**1. M（保留数量）**
- 每个 N 长度周期中保留多少个项目
- 通常应满足 `0 < M <= N`

**2. N（周期长度）**
- 每 N 个输入项目构成一个周期
- 输出速率约为输入速率的 `M / N`

**3. initial offset（初始偏移）**
- 改变保留窗口相对输入起点的位置
- 用于对齐帧结构或时隙

**4. Type（数据类型）**
- 输入和输出类型相同
- 模块不改变样本值

## 工作原理

```
输入:  0 1 2 3 4 5 6 7 ...
M=2,N=4
输出: 0 1     4 5 ...
```

如果设置 offset，可以改变从周期内哪个位置开始保留。

## 快速示例

**示例 1：周期性保留窗口**

```
[Source] → [Keep M in N] → [Processing]
            M=10, N=100
```

**示例 2：帧内字段提取**

```
[Frame Stream] → [Keep M in N] → [Field Processing]
                 M=64, N=256, offset=16
```

**示例 3：调试降载**

```
[High Rate Stream] → [Keep M in N] → [QT GUI Time Sink]
```

## 配置注意

1. **按 item 计数**  
   对向量流来说，M 和 N 统计的是向量 item，不是向量内部元素。

2. **offset 用于对齐**  
   如果输出窗口错位，优先检查 initial offset。

3. **不能替代滤波抽取**  
   输出速率降低并不代表频谱无混叠。

## 性能与部署

在目标采样率和数据规模下验证 CPU、内存与端到端延迟。动态参数、向量长度和并行通道增加时应重新测量。

## 故障排查

**Q1: M 可以大于 N 吗？**  
A: 不应该。通常需要满足 `0 < M <= N`。

**Q2: offset 用来做什么？**  
A: 用于改变保留窗口在周期内的起始位置。

**Q3: 与 Keep 1 in N 有什么关系？**  
A: Keep 1 in N 是 M=1 的常见特例，但接口更简单。
